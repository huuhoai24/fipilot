# Software Engineer - Middle Level Knowledge Depth & Evaluation

### Knowledge Depth

The candidate should:

- Deeply understand software design and how to decompose a system into modules with clear responsibilities.
- Analyze assumptions and limitations of design patterns and architectural patterns.
- Evaluate trade-offs among abstraction, flexibility, simplicity and performance.
- Understand cohesion, coupling, dependency direction and boundary design.
- Analyze concurrency issues such as race condition, deadlock, starvation and synchronization overhead.
- Understand consistency, transactions, idempotency and fault handling in multi-component systems.
- Analyze API design, contracts, versioning and backward compatibility.
- Understand caching strategy, asynchronous processing and event-driven architecture at an analytical level.
- Evaluate testing strategy based on risk, system boundary and failure mode.
- Analyze bottlenecks, memory leaks, latency and throughput at a system level.
- Understand observability including logging, metrics, tracing and error reporting.
- Analyze failure modes, root causes and recovery strategies.
- Understand secure design, threat modeling and common application vulnerabilities.
- Evaluate technical debt, refactoring cost and long-term maintainability.
- Determine when a design pattern or architecture is no longer appropriate.

### Evaluation Focus

- Analysis.
- Assumptions.
- Failure modes.
- Root causes.
- Trade-offs.
- Software design.
- Concurrency.
- Reliability.
- Security.
- Maintainability.
- Conditions for solution selection.
