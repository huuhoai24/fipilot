# Back End Developer - Middle Level Knowledge Depth & Evaluation

### Knowledge Depth

The candidate should:

- Deeply understand how backend components interact within a complete system.
- Analyze the boundaries among the API layer, application layer, domain layer and infrastructure layer.
- Evaluate when to use layered architecture, modular monolith or microservices.
- Understand coupling, cohesion, dependency direction and abstraction boundaries.
- Analyze API contracts, backward compatibility, versioning and deprecation.
- Understand concurrency, parallelism, synchronization and shared-state problems.
- Analyze race conditions, deadlocks, lost updates and idempotency.
- Understand transaction boundaries, distributed transactions and eventual consistency.
- Evaluate isolation levels based on consistency and concurrency requirements.
- Analyze query plans, index strategies, cardinality and database bottlenecks.
- Understand replication, partitioning, sharding and read/write scaling at a system level.
- Analyze cache-aside, write-through, write-behind and cache invalidation.
- Understand cache stampede, stale data and consistency between cache and database.
- Evaluate message brokers, queues, event streams and event-driven architecture.
- Understand delivery semantics such as at-most-once, at-least-once and exactly-once within specific scopes.
- Analyze timeout, retry, exponential backoff, circuit breaker and bulkhead.
- Understand failure propagation and graceful degradation.
- Analyze latency, throughput, CPU, memory, connection limits and resource saturation.
- Understand observability through logs, metrics, traces and correlation identifiers.
- Evaluate authentication, authorization, tenant isolation and secret management.
- Analyze risks such as SQL injection, SSRF, insecure deserialization and broken access control.
- Understand deployment strategies, health checks, rollback and zero-downtime changes.
- Analyze database migration compatibility across application versions.
- Evaluate root causes rather than merely describing symptoms.
- Articulate assumptions, failure modes, verification methods and residual risks of a technical decision.

### Evaluation Focus

- Analysis.
- Assumptions.
- Failure modes.
- Root causes.
- Trade-offs.
- Consistency.
- Concurrency.
- Scalability.
- Reliability.
- Security.
- Observability.
- Conditions for architecture selection.
