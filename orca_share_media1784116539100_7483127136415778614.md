# AI Interview Platform — Design Specification

**Version:** 1.0  
**Date:** 2025-06-19  
**Role Target:** AI Engineer (Data-AI), Level 3, 4–5 years experience

---

## 1. Product Overview

An AI-powered interview management platform that automates the full interview lifecycle — from CV upload and candidate matching through AI-driven voice interviews to evaluation and history logging. Built for interviewers, HR admins, and candidates.

### 1.1 Core Modules

| Module | Description |
|---|---|
| **Interview Settings** | Configure interview parameters, difficulty levels, time limits, scoring rubrics |
| **Interview Flow** | End-to-end pipeline: CV upload → extraction → template matching → AI agent interview → logging → evaluation |
| **QnA Template Manager** | Create, edit, tag, and version Q&A pairs organized by role, level, and difficulty |
| **Interview History** | View past sessions, transcripts, evaluation scores, and comparison reports |

## 3. Module Specifications

### 3.1 Interview Settings

**Purpose:** Define reusable configuration profiles for interview sessions.

**Data Model: `InterviewConfig`**
```json
{
  "id": "uuid",
  "name": "AI Engineer L3 — Standard",
  "role": "data-ai",
  "level": 3,
  "duration_minutes": 45,
  "difficulty_mix": { "easy": 3, "medium": 4, "hard": 3 },
  "voice_enabled": true,
  "avatar_enabled": false,
  "scoring_rubric": "default_l3",
  "language": "vi",
  "created_by": "admin_uuid",
  "created_at": "ISO8601"
}
```

**UI Components:**
- Config name + role/level dropdowns
- Duration slider (15–120 min)
- Difficulty distribution sliders (easy / medium / hard count)
- Toggle: Voice Interview, Avatar, Auto-Evaluate
- Scoring Rubric selector
- Language selector (vi / en)
- Save as Template button

---

### 3.2 QnA Template Manager

**Purpose:** Create and manage structured question-answer pairs used by the interview agent.

**Data Model: `QnATemplate`**
```json
{
  "id": "uuid",
  "title": "AI Engineer Level 3",
  "role": "data-ai",
  "level": 3,
  "version": "1.2",
  "questions": [
    {
      "id": "q_001",
      "difficulty": "easy",
      "question": "Sự khác nhau giữa Fine-tuning và Prompt Engineering là gì?",
      "sample_answer": "Fine-tuning cập nhật trọng số...",
      "tags": ["llm", "prompt", "fine-tuning"],
      "score_weight": 1.0
    }
  ],
  "embedding_vector": "[float array]",
  "created_by": "admin_uuid",
  "updated_at": "ISO8601"
}
```

**Features:**
- CRUD for templates and individual questions
- Bulk import from Markdown (as per uploaded `AI_Engineer_Level3_Interview_Questions.md` format)
- Tag management (role, topic, difficulty)
- Version history with diff view
- Template duplication / fork
- Embedding regeneration trigger (for vector search)
- Preview: how the agent will present questions

**Matching Algorithm:**
1. Extract structured skills/level from CV (LLM output)
2. Embed CV summary → vector
3. Cosine similarity search against `QnATemplate.embedding_vector` in pgvector
4. Re-rank by: JD match score × difficulty alignment × recency
5. Return top-5 templates with match scores

### 3.3 Interview Flow

#### Step 1 — CV Upload & Extraction

**Input:** PDF/DOCX CV file  
**Process:** LLM (GPT-4o / Claude) extracts structured JSON

```json
{
  "candidate_name": "Nguyen Van A",
  "years_experience": 4.5,
  "skills": ["Python", "PyTorch", "LLM fine-tuning", "RAG", "MLOps"],
  "education": "Bachelor CS, HUST 2020",
  "recent_role": "ML Engineer @ FPT",
  "inferred_level": 3,
  "role_fit": "data-ai"
}
```

**API:**
```
POST /api/v1/cv/extract
Content-Type: multipart/form-data
Body: { file: <binary>, session_id: uuid }

Response: { candidate_profile: {...}, confidence: 0.92 }
```

---

#### Step 2 — Template Matching

```
POST /api/v1/templates/match
Body: { candidate_profile: {...}, jd_id: "uuid", top_k: 5 }

Response: {
  matches: [
    { template_id: "uuid", title: "...", score: 0.94 },
    ...
  ]
}
```

Admin reviews and selects the template, then triggers interview session creation.

---

#### Step 3 — AI Voice Interview

**Architecture:**
- **Interviewer Bot** (SLM — Small Language Model, on-device or edge) runs the Q&A loop
- **Voice I/O:** WebRTC for real-time audio; STT (Whisper) + TTS (ElevenLabs or local)
- **Avatar (optional):** animated avatar using blendshape-driven lip sync
- **Session State:** Redis pub/sub for real-time transcript streaming

**Interview Agent Behavior:**
```
For each question in template:
  1. Agent speaks question (TTS)
  2. Wait for candidate answer (STT → transcript)
  3. Log Q + A pair with timestamp
  4. Optional: agent asks 1 follow-up if answer is insufficient
  5. Move to next question
End: Agent closes session, thanks candidate
```

**Real-time Events (WebSocket):**
```
ws://server/interview/{session_id}

Events:
  agent:question  → { question_id, text, audio_url }
  candidate:answer → { question_id, transcript, duration_ms }
  session:end     → { total_questions, duration_s }
```

---

#### Step 4 — Log to DB

**Data Model: `InterviewSession`**
```json
{
  "id": "uuid",
  "candidate_id": "uuid",
  "template_id": "uuid",
  "config_id": "uuid",
  "started_at": "ISO8601",
  "ended_at": "ISO8601",
  "status": "completed | interrupted | no_show",
  "transcript": [
    {
      "question_id": "q_001",
      "question_text": "...",
      "answer_text": "...",
      "answer_audio_url": "s3://...",
      "duration_ms": 42000
    }
  ],
  "raw_audio_url": "s3://..."
}
```

---

#### Step 5 — Evaluate

**Process:** LLM evaluates each Q&A pair against sample answers.

**Output: `InterviewEvaluation`**
```json
{
  "session_id": "uuid",
  "overall_score": 7.4,
  "max_score": 10,
  "per_question": [
    {
      "question_id": "q_001",
      "score": 8,
      "issues": [],
      "suggestion": "Good coverage. Could mention LoRA for parameter-efficient fine-tuning."
    },
    {
      "question_id": "q_009",
      "score": 5,
      "issues": ["Did not mention class weighting"],
      "suggestion": "Expand on SMOTE and threshold calibration."
    }
  ],
  "summary": "Candidate demonstrates solid fundamentals with gaps in production monitoring.",
  "hire_recommendation": "consider",
  "generated_at": "ISO8601"
}
```

### 3.4 Interview History

**Features:**
- List view: all sessions, filterable by date / role / score / status
- Session detail: full transcript + audio playback + evaluation scores
- Score trend chart per candidate (if multiple sessions)
- Export to PDF / CSV
- Compare two candidates side by side
- Evaluation re-run trigger (if template updated)

**API:**
```

GET /api/v1/history/{session_id}
GET /api/v1/history/{session_id}/evaluation
POST /api/v1/history/{session_id}/export?format=pdf
```

## 7. Security & Compliance

- All audio and CV data encrypted at rest (AES-256) and in transit (TLS 1.3)
- Role-based access: `admin` (full), `interviewer` (conduct + history), `candidate` (own session only)
- CV files purged after 90 days (configurable), audio after 30 days
- PII masking in logs (candidate names replaced with UUID in system logs)
- Rate limiting on all LLM-backed endpoints (10 req/min per user)
- Audit log for all admin actions (template edits, config changes)

- Custom scoring rubric builder
- Integration with ATS (Greenhouse, Workday)
- Interview scheduling + calendar invite
