# Bộ Câu Hỏi Phỏng Vấn Business Analyst (Level 3) - Elicitation Techniques Nâng cao (12)

* **Role:** Business Analyst
* **Level:** Level 3
* **Experience:** 4 - 5 năm kinh nghiệm

---

## CÂU HỎI DỄ (3 câu - Trọng số: 0.1 / câu)

### Câu 1
* **Độ khó:** Dễ
* **Câu hỏi:** So sánh ít nhất 5 kỹ thuật elicitation. Khi nào bạn chọn technique nào?
* **expected_key_points:**
  - id: KP1
    content: Interview vs Workshop vs Observation
    keypoint_weight: 0.4
    description: Interview: deep-dive 1-on-1. Workshop: group consensus. Observation: understand actual vs stated process.
  - id: KP2
    content: Survey vs Document Analysis vs Prototyping
    keypoint_weight: 0.35
    description: Survey: large audience. Document: existing knowledge. Prototyping: visualize requirements.
  - id: KP3
    content: Selection criteria
    keypoint_weight: 0.25
    description: Stakeholder availability, project phase, complexity, team familiarity, time constraints.

### Câu 2
* **Độ khó:** Dễ
* **Câu hỏi:** Bạn dùng kỹ thuật gì để phát hiện 'hidden requirements' - yêu cầu mà stakeholders không nói ra?
* **expected_key_points:**
  - id: KP1
    content: Observation và contextual inquiry
    keypoint_weight: 0.4
    description: Quan sát user thực tế làm việc, phát hiện workarounds, manual steps, frustrations họ đã quen.
  - id: KP2
    content: Negative scenarios và edge cases
    keypoint_weight: 0.35
    description: Hỏi: 'Điều gì xảy ra nếu...?', 'Trường hợp nào system hiện tại không handle được?'
  - id: KP3
    content: Competitor analysis và industry benchmarks
    keypoint_weight: 0.25
    description: Review competitor features mà users expect but don't articulate explicitly.

### Câu 3
* **Độ khó:** Dễ
* **Câu hỏi:** Story Mapping là gì? Bạn facilitate một story mapping session như thế nào?
* **expected_key_points:**
  - id: KP1
    content: User Story Map structure
    keypoint_weight: 0.4
    description: Backbone (user activities) → Walking skeleton (main user tasks) → Details (user stories) arranged vertically by priority.
  - id: KP2
    content: Facilitation approach
    keypoint_weight: 0.35
    description: Post-it notes, collaborative exercise, involve dev + business, timebox activities.
  - id: KP3
    content: Output: release planning
    keypoint_weight: 0.25
    description: Horizontal slices define releases/MVPs, ensuring each release delivers complete user journey.

## CÂU HỎI TRUNG BÌNH (4 câu - Trọng số: 0.1 / câu)

### Câu 4
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn facilitate một JAD (Joint Application Design) session cho dự án phức tạp. Mô tả preparation, execution, và follow-up.
* **expected_key_points:**
  - id: KP1
    content: Pre-session preparation
    keypoint_weight: 0.25
    description: Define scope, identify participants, create agenda, pre-read materials, logistics planning.
  - id: KP2
    content: Session facilitation techniques
    keypoint_weight: 0.3
    description: Ground rules, parking lot, timeboxing, visual modeling live, consensus-building techniques.
  - id: KP3
    content: Conflict resolution in-session
    keypoint_weight: 0.25
    description: Acknowledge disagreements, use data to arbitrate, escalation path, voting if needed.
  - id: KP4
    content: Post-session deliverables
    keypoint_weight: 0.2
    description: Session notes, updated requirements, action items, follow-up meetings, sign-off on decisions.

### Câu 5
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn elicit requirements cho một AI/ML feature (recommendation engine). Approach khác gì so với traditional features?
* **expected_key_points:**
  - id: KP1
    content: Probabilistic vs deterministic requirements
    keypoint_weight: 0.3
    description: ML outputs are predictions with confidence scores, not exact answers. Define acceptable accuracy thresholds.
  - id: KP2
    content: Training data requirements
    keypoint_weight: 0.25
    description: Data volume, quality, labeling, bias assessment, data pipeline requirements.
  - id: KP3
    content: Feedback loop design
    keypoint_weight: 0.25
    description: How users provide implicit/explicit feedback, model retraining triggers, A/B testing framework.
  - id: KP4
    content: Explainability requirements
    keypoint_weight: 0.2
    description: Why was this recommended? User-facing explanations, business-level model interpretability.

### Câu 6
* **Độ khó:** Trung bình
* **Câu hỏi:** Mô tả cách bạn elicit requirements từ remote/distributed stakeholders across multiple time zones.
* **expected_key_points:**
  - id: KP1
    content: Asynchronous elicitation techniques
    keypoint_weight: 0.3
    description: Online surveys, shared documents with comment threads, video recordings, collaborative boards (Miro).
  - id: KP2
    content: Synchronous session optimization
    keypoint_weight: 0.25
    description: Rotating meeting times, pre-read to minimize meeting time, focused agenda, recording for absentees.
  - id: KP3
    content: Cultural awareness
    keypoint_weight: 0.25
    description: Different communication styles, decision-making norms, language barriers, power distance.
  - id: KP4
    content: Tool stack for distributed BA
    keypoint_weight: 0.2
    description: Confluence/SharePoint for docs, Jira for requirements, Miro for workshops, Slack for quick clarifications.

### Câu 7
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn dùng Event Storming để khám phá domain model cho hệ thống mới. Mô tả process và output.
* **expected_key_points:**
  - id: KP1
    content: Big Picture Event Storming
    keypoint_weight: 0.3
    description: Identify domain events (orange), commands (blue), actors (yellow), external systems (pink) on timeline.
  - id: KP2
    content: Process Modeling level
    keypoint_weight: 0.25
    description: Detail processes, identify policies, read models, và hotspots (areas of confusion/disagreement).
  - id: KP3
    content: Bounded context identification
    keypoint_weight: 0.25
    description: Group related events into bounded contexts, identify context boundaries và integration points.
  - id: KP4
    content: Output artifacts
    keypoint_weight: 0.2
    description: Domain model, bounded contexts map, glossary (ubiquitous language), hotspot list for further analysis.

## CÂU HỎI KHÓ (3 câu - Trọng số: 0.1 / câu)

### Câu 8
* **Độ khó:** Khó
* **Câu hỏi:** Bạn cần elicit requirements cho một platform serving both B2B và B2C customers với conflicting needs. Approach?
* **expected_key_points:**
  - id: KP1
    content: Dual persona development
    keypoint_weight: 0.3
    description: Separate persona sets cho B2B (admin, end-user, procurement) và B2C (individual consumer). Identify overlaps.
  - id: KP2
    content: Requirements conflict resolution framework
    keypoint_weight: 0.25
    description: Matrix mapping conflicts, prioritization criteria (revenue impact, user volume, strategic importance).
  - id: KP3
    content: Platform vs product thinking
    keypoint_weight: 0.25
    description: Shared core platform capabilities vs specialized experiences. Configuration vs customization boundaries.
  - id: KP4
    content: Multi-tenant architecture implications
    keypoint_weight: 0.2
    description: Data isolation, feature toggles, branding customization, billing model differences B2B vs B2C.

### Câu 9
* **Độ khó:** Khó
* **Câu hỏi:** Thiết kế requirements elicitation strategy cho IoT smart building management system với diverse stakeholder groups (facility managers, tenants, engineers).
* **expected_key_points:**
  - id: KP1
    content: Stakeholder-specific elicitation
    keypoint_weight: 0.3
    description: Facility managers: operational efficiency. Tenants: comfort, convenience. Engineers: system monitoring, maintenance.
  - id: KP2
    content: Physical environment observation
    keypoint_weight: 0.25
    description: Site visits, shadowing facility staff, understanding physical constraints, sensor placement requirements.
  - id: KP3
    content: Cross-cutting concerns
    keypoint_weight: 0.25
    description: Energy optimization vs comfort, security vs convenience, automation vs manual override. Trade-off analysis.
  - id: KP4
    content: Iterative prototyping with sensors
    keypoint_weight: 0.2
    description: POC with limited sensors, validate assumptions, adjust requirements based on real data before full rollout.

### Câu 10
* **Độ khó:** Khó
* **Câu hỏi:** Bạn áp dụng Design Thinking combined với BA techniques cho innovation project. Mô tả integrated approach.
* **expected_key_points:**
  - id: KP1
    content: Empathize phase + BA elicitation
    keypoint_weight: 0.3
    description: User interviews, ethnographic research, empathy maps combined với traditional stakeholder analysis.
  - id: KP2
    content: Define + Problem framing
    keypoint_weight: 0.25
    description: How Might We statements, point-of-view statements, problem decomposition using business analysis.
  - id: KP3
    content: Ideate + Requirements emergence
    keypoint_weight: 0.25
    description: Brainstorming, crazy 8s, concept selection → translate winning concepts into epics/features.
  - id: KP4
    content: Prototype + Validate
    keypoint_weight: 0.2
    description: Rapid prototyping, user testing, iterate. BA document validated requirements from successful prototypes.
