# Bộ Câu Hỏi Phỏng Vấn Business Analyst (Level 3) - UX/UI Analysis & Wireframing (6)

* **Role:** Business Analyst
* **Level:** Level 3
* **Experience:** 4 - 5 năm kinh nghiệm

---

## CÂU HỎI DỄ (3 câu - Trọng số: 0.1 / câu)

### Câu 1
* **Độ khó:** Dễ
* **Câu hỏi:** Bạn sử dụng wireframe và mockup trong quy trình phân tích yêu cầu như thế nào? Phân biệt low-fidelity và high-fidelity.
* **expected_key_points:**
  - id: KP1
    content: Low-fidelity wireframe
    keypoint_weight: 0.35
    description: Sketch nhanh trên giấy hoặc tool đơn giản, tập trung layout và information architecture, dùng trong discovery phase.
  - id: KP2
    content: High-fidelity mockup/prototype
    keypoint_weight: 0.35
    description: Thiết kế chi tiết với colors, typography, interactions, dùng để validate với stakeholders trước development.
  - id: KP3
    content: BA role trong UX process
    keypoint_weight: 0.3
    description: BA cung cấp business rules, user flows, edge cases cho UX designer, review wireframes từ góc nhìn nghiệp vụ.

### Câu 2
* **Độ khó:** Dễ
* **Câu hỏi:** User Persona là gì? Bạn tạo persona dựa trên dữ liệu gì và sử dụng nó ở đâu trong dự án?
* **expected_key_points:**
  - id: KP1
    content: Định nghĩa và cấu trúc persona
    keypoint_weight: 0.4
    description: Đại diện fictional của user group: demographics, goals, pain points, behavior patterns, technical proficiency.
  - id: KP2
    content: Data sources cho persona
    keypoint_weight: 0.3
    description: User interviews, surveys, analytics data, customer support logs, market research.
  - id: KP3
    content: Ứng dụng trong quyết định design
    keypoint_weight: 0.3
    description: Dùng persona để prioritize features, viết user stories, và validate design decisions từ góc nhìn user.

### Câu 3
* **Độ khó:** Dễ
* **Câu hỏi:** Customer Journey Map và User Flow khác nhau thế nào? Khi nào BA cần tạo từng loại?
* **expected_key_points:**
  - id: KP1
    content: Customer Journey Map: trải nghiệm tổng thể
    keypoint_weight: 0.4
    description: Map toàn bộ touchpoints, emotions, pain points của customer qua multiple channels, cả online và offline.
  - id: KP2
    content: User Flow: luồng tương tác trong hệ thống
    keypoint_weight: 0.35
    description: Chi tiết các bước user thực hiện trong ứng dụng để hoàn thành 1 task cụ thể.
  - id: KP3
    content: Bổ trợ lẫn nhau
    keypoint_weight: 0.25
    description: Journey Map cho big picture strategy, User Flow cho detailed system design.

## CÂU HỎI TRUNG BÌNH (4 câu - Trọng số: 0.1 / câu)

### Câu 4
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn thiết kế information architecture cho một ứng dụng enterprise có 50+ features. Approach và deliverables là gì?
* **expected_key_points:**
  - id: KP1
    content: Card sorting và tree testing
    keypoint_weight: 0.3
    description: Dùng card sorting với users để nhóm features, tree testing để validate navigation structure.
  - id: KP2
    content: Sitemap và navigation hierarchy
    keypoint_weight: 0.25
    description: Tạo sitemap multi-level, cân nhắc primary/secondary/utility navigation, breadcrumbs.
  - id: KP3
    content: Role-based information access
    keypoint_weight: 0.25
    description: Khác biệt IA cho từng user role, personalized dashboards, progressive disclosure.
  - id: KP4
    content: Content strategy alignment
    keypoint_weight: 0.2
    description: Đảm bảo IA support content types, taxonomy, tagging system, và search functionality.

### Câu 5
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn cần thu thập usability feedback từ end-users cho ứng dụng hiện tại trước khi redesign. Mô tả research plan.
* **expected_key_points:**
  - id: KP1
    content: Usability testing methodology
    keypoint_weight: 0.3
    description: Task-based testing với 5-8 representative users, think-aloud protocol, recording sessions.
  - id: KP2
    content: Heuristic evaluation
    keypoint_weight: 0.25
    description: Áp dụng Nielsen's 10 heuristics để đánh giá systematic, identify usability violations.
  - id: KP3
    content: Quantitative metrics
    keypoint_weight: 0.25
    description: SUS (System Usability Scale) score, task completion rate, time-on-task, error rate.
  - id: KP4
    content: Synthesis và prioritization
    keypoint_weight: 0.2
    description: Affinity mapping findings, severity rating, recommendations prioritized by impact vs effort.

### Câu 6
* **Độ khó:** Trung bình
* **Câu hỏi:** Bạn xử lý thế nào khi business requirements mâu thuẫn với UX best practices? Cho ví dụ cụ thể.
* **expected_key_points:**
  - id: KP1
    content: Evidence-based advocacy
    keypoint_weight: 0.3
    description: Dùng data (analytics, user testing results) để support UX recommendation, không chỉ opinion.
  - id: KP2
    content: Compromise solutions
    keypoint_weight: 0.25
    description: Tìm middle ground: thỏa mãn business goal nhưng minimize UX trade-offs.
  - id: KP3
    content: A/B test proposal
    keypoint_weight: 0.25
    description: Đề xuất test cả 2 approaches nếu không đồng thuận, let data decide.
  - id: KP4
    content: Document decision và rationale
    keypoint_weight: 0.2
    description: Ghi lại trade-off discussion, decision, người quyết định, và metrics để revisit sau.

### Câu 7
* **Độ khó:** Trung bình
* **Câu hỏi:** Mô tả cách bạn viết UI specifications cho development team, đảm bảo consistency across screens.
* **expected_key_points:**
  - id: KP1
    content: Component-based specification
    keypoint_weight: 0.3
    description: Document UI components: behavior, states (default, hover, active, disabled, error), variations.
  - id: KP2
    content: Design system reference
    keypoint_weight: 0.25
    description: Tham chiếu design system/style guide cho typography, colors, spacing, iconography.
  - id: KP3
    content: Interaction specifications
    keypoint_weight: 0.25
    description: Chi tiết animations, transitions, loading states, empty states, error handling UI.
  - id: KP4
    content: Responsive behavior
    keypoint_weight: 0.2
    description: Breakpoints definition, layout changes across desktop/tablet/mobile, touch vs click considerations.

## CÂU HỎI KHÓ (3 câu - Trọng số: 0.1 / câu)

### Câu 8
* **Độ khó:** Khó
* **Câu hỏi:** Thiết kế UX requirements cho hệ thống healthcare patient portal tuân thủ WCAG 2.1 AA accessibility standards. Approach và key considerations?
* **expected_key_points:**
  - id: KP1
    content: WCAG 2.1 AA compliance requirements
    keypoint_weight: 0.3
    description: Perceivable, Operable, Understandable, Robust principles. Color contrast ratios, keyboard navigation, screen reader support.
  - id: KP2
    content: Healthcare-specific UX patterns
    keypoint_weight: 0.25
    description: Patient data display, medication management, appointment booking flows phù hợp cho elderly và disabled users.
  - id: KP3
    content: HIPAA và privacy considerations
    keypoint_weight: 0.25
    description: Session timeout, data masking, consent management, audit trail cho data access.
  - id: KP4
    content: Multi-device và offline capability
    keypoint_weight: 0.2
    description: Responsive design cho diverse devices, progressive web app cho limited connectivity areas.

### Câu 9
* **Độ khó:** Khó
* **Câu hỏi:** Bạn cần thiết kế một complex dashboard cho operations team hiển thị real-time data từ IoT sensors. Trình bày approach phân tích.
* **expected_key_points:**
  - id: KP1
    content: Information hierarchy và cognitive load
    keypoint_weight: 0.3
    description: Prioritize critical alerts, progressive disclosure, avoid information overload, pre-attentive attributes.
  - id: KP2
    content: Real-time data visualization patterns
    keypoint_weight: 0.25
    description: Sparklines, gauges, heatmaps cho live data. Threshold-based color coding, trend indicators.
  - id: KP3
    content: Alert và notification system
    keypoint_weight: 0.25
    description: Tiered alerting (info, warning, critical), snooze/acknowledge flows, escalation rules.
  - id: KP4
    content: Performance requirements for real-time UI
    keypoint_weight: 0.2
    description: WebSocket vs polling, data sampling strategy, client-side rendering optimization.

### Câu 10
* **Độ khó:** Khó
* **Câu hỏi:** Phân tích và đề xuất giải pháp cho việc redesign một legacy enterprise application (15+ năm) sang modern UX mà không disrupt operations.
* **expected_key_points:**
  - id: KP1
    content: Strangler fig pattern cho UX
    keypoint_weight: 0.3
    description: Gradual replacement: wrap legacy screens trong modern shell, replace module by module.
  - id: KP2
    content: User change management
    keypoint_weight: 0.25
    description: Training plan, parallel run period, feature parity assessment, power user champion program.
  - id: KP3
    content: Data migration và UX consistency
    keypoint_weight: 0.25
    description: Đảm bảo data hiển thị consistent giữa old và new modules, unified navigation.
  - id: KP4
    content: Success metrics cho redesign
    keypoint_weight: 0.2
    description: User adoption rate per module, support ticket reduction, task completion time improvement.
